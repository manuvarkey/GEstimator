## Format and authority

An `.eproj` file is a SQLite database. The canonical schema is
[`get_orm_model`](../../estimator/data/schedule.py); project defaults and the
current marker are in [`estimator/misc.py`](../../estimator/misc.py).
The file version is a key/value row in `projecttable`, not a separate column:

```text
key: file_version
value: GESTIMATOR_FILE_REFERENCE_VER_2
```

The modern open path copies a read-only source into a temporary working database
using SQLite backup, then validates/migrates the copy. Version 1 migration adds
the schedule colour field and updates the marker in one transaction. If either
step fails, the copy keeps its original column layout and version marker. Never
invoke the engine's migration directly on an attached library or an original
user file. Follow [the project file commands](../../modern/backend/project_files.py) for the open
sequence and [the database lifecycle module](../../estimator/data/database_lifecycle.py)
for the engine transaction.

The [original design spreadsheet](<../../design documentation/database design_initial.ods>)
is historical evidence, not the current schema specification.

## Core tables

Names below are physical table/column names generated by the current Peewee
models. SQLite identifiers are case-insensitive. Except `projecttable`, each
table has an integer `id` primary key.

| Table | Columns beyond `id` | Constraints and meaning |
| --- | --- | --- |
| `projecttable` | `key`, `value` | `key` is the primary key; values are strings, including serialized JSON |
| `schedulecategorytable` | `description`, `order` | Unique description; explicit display order |
| `resourcecategorytable` | `description`, `order` | Unique description; explicit display order |
| `scheduletable` | `code`, `description`, `unit`, `rate`, `qty`, `remarks`, `ana_remarks`, `category_id`, `parent_id`, `order`, `suborder`, `colour` | Unique code; nullable category and parent foreign keys; nullable unit, numeric values, remarks, suborder and colour |
| `resourcetable` | `code`, `description`, `unit`, `rate`, `vat`, `discount`, `reference`, `category_id`, `order` | Unique code; nullable VAT, discount, reference and category; rate/unit required |
| `sequencetable` | `id_seq`, `id_sch_id`, `itemtype`, `value`, `code`, `description` | Unique `(id_seq, id_sch_id)`; ordered analysis rows for a schedule item; value/code/description nullable |
| `resourceitemtable` | `id_sch_id`, `id_seq_id`, `id_res_id`, `qty`, `remarks` | Resource uses within an analysis group; remarks nullable |

Foreign keys use cascade deletion. `category_id` points to the corresponding
category table; `parent_id` points to `scheduletable.id`. Resource-use foreign
keys point to schedule, sequence and resource primary keys respectively.
`open_database` enables `PRAGMA foreign_keys=ON` on engine connections.

`sequencetable.id_seq` is the sequence position; `resourceitemtable.id_seq_id`
is a foreign key to the sequence row's primary key. Do not confuse these when
writing queries or changing import/export code.

### Numeric storage

Peewee models expose Decimal fields. Schedule/resource rates and resource
discounts declare two decimal places with `auto_round=True`; VAT declares four.
Schedule quantities, sequence values and resource-use quantities inherit the
Peewee DecimalField defaults (currently five declared decimal places with
`auto_round=False`). These declarations are not a substitute for application
validation or guarantees that SQLite arithmetic is exact.

Use the engine and [numeric evaluation contract](backend.md#numeric-evaluation)
for calculations and entry rounding. Preserve Decimal strings over IPC. Do not
recalculate money with JavaScript numbers or raw SQLite floating-point SUMs;
MCP reporting deliberately exposes numeric values as text and has separate limits.

### Ordering and identities

Category `order`, item `order` and schedule `suborder` define application order.
The supported schedule editor hierarchy is parent plus child; do not introduce
deeper nesting without a deliberate compatibility change. Keep SUB ANALYSIS
after ordinary categories through
[`keep_sub_analysis_last`](../../modern/backend/insertion.py).

Database primary keys, source-qualified item codes, session row UUIDs and MCP
positional analysis aliases are different identities. Session UUIDs and undo
histories are not new columns in the project format. Preserve record IDs with
their values during drafts, undo and row moves; never persist frontend selection
or a table's visible order as the authoritative data model.

## Project settings and measurements

Default keys are `file_version`, `project_name`, `project_item_code`,
`project_resource_code` and `project_measurement`. `project_metadata` optionally
holds author-maintained database notes in Markdown. See
[`metadata.py`](../../modern/backend/metadata.py) for `## Category: <name>` note
sections and [MCP source notes](mcp.md#sources-and-placement).

`project_report_specification` optionally stores the version-one report definition
as bounded JSON. It is additive metadata: no file-version/table change is required.
The [report contract](../features/report-documents.md#saved-report-definitions)
owns validation, unsupported-data preservation and Apply/Save behavior. Report
snapshots/previews never write this key. Explicit Apply uses project transactions
and undo; ordinary saves/recovery copy it with the other project data. Persisted
row filters are excluded until their deletion/ID-reuse lifecycle is implemented.

`project_measurement` contains JSON from
[`Measurement.get_model`](../../estimator/data/measurement.py):

```text
["Measurement", [caption, items]]

heading item:
["MeasurementItemHeading", [remark]]

custom item:
["MeasurementItemCustom", [itemnos, records, remark, item_remarks, user_data, itemtype]]
```

`itemnos` contains linked schedule primary keys or null values; `item_remarks`
contains per-link remarks. `records` holds lists of raw cell strings, preserving
expressions. `itemtype` selects a trusted installed Python template by its
validated name. Template callbacks derive display and totals; do not replace
raw record strings with formatted values or serialized callback code.

These schedule links live inside JSON and are not SQL foreign keys. Schedule
deletion must clear affected links while retaining measurement records/remarks;
otherwise SQLite key reuse can silently retarget them. Test undo restoring links
as well as SQL rows. Template numeric types and rounding are documented in the
[backend contract](backend.md#measurements-and-templates).

## Optional metadata and derived data

`meta_enrichment(scope TEXT PRIMARY KEY, data TEXT NOT NULL)` is optional.
[`metadata.py`](../../modern/backend/metadata.py) reads schema-1 JSON and ignores
invalid optional documents; the database scope contains summaries, category/item
annotations and provenance. Original descriptions, codes and numeric definitions
remain authoritative. Missing enrichment must not prevent ordinary use.

Search indexes and the MCP `v_*` reporting views are derived outside source
files. Reporting views are built in a disposable projection, not installed into
user/library databases. Their columns are owned by
[`mcp_query.SCHEMA`](../../modern/backend/mcp_query.py), described by
`describe_source section=schema` and governed by the [MCP contract](mcp.md#sql-fallback).

## Working copies, save and recovery

- Edits affect an isolated working database. Attached databases are snapshots
  and are never edited in place.
- Save Copy exclusively creates a new destination. Save checks the original's
  fingerprint/journals, stages a complete snapshot, preserves a numbered sibling
  backup and replaces the original under an advisory save lock.
  On Flatpak, a writable file grant supports in-place Save directly. Backups
  for a single-file grant live in the app's data directory under
  `project-backups`. A read-only file grant needs a writable folder selection.
  GEstimator verifies that both grants identify the same unchanged project
  and keeps backups beside the project when using the folder grant. Flatpak
  instances lock in the shared app runtime directory using the project's
  portal-reported host path as the identity.
  The Flatpak Save Copy chooser can confirm replacement of an existing file.
  GEstimator stages the complete copy and preserves the previous file before
  replacement. Direct path requests still require an unused filename.
- Recovery writes staged snapshots and uses per-copy OS claims to keep active
  documents in other processes from offering/deleting the same recovery copy.
  Recovery includes pending analysis/record drafts; it does not persist undo history.
- Apply changes working-project data. Saving is a separate file operation and
  must not mark drafts clean before publication succeeds.

The owners are [`Service`](../../modern/backend/service.py),
[`ProjectEditor`](../../modern/backend/project.py) and
[`persistence.py`](../../modern/backend/persistence.py). The save lock coordinates
participating app instances; it is not a lock imposed on every external editor.

## Changing this contract

Start with [development rules](../../AGENTS.md) and [backend transaction ownership](backend.md).
A schema/format change requires an explicit migration plan, original-file
preservation, round-trip coverage and updated documentation. Verify SQLite
integrity and foreign keys, measurement link behavior, Decimal results, undo,
save/reopen and workbook output using disposable copies of bundled data.

Relevant tests include [modern backend](../../tests/test_modern_backend.py),
[project editors](../../tests/test_project_editors.py),
[record drafts](../../tests/test_records_draft.py),
[clipboard](../../tests/test_clipboard.py),
[document sessions](../../tests/test_document_sessions.py) and
[MCP queries](../../tests/test_mcp_query.py). Follow the [testing guide](../testing.md)
and record actual results in the [validation log](../migration/validation.md).


### Estimate field defaults

`project_estimate_fields` is an optional JSON ProjectTable value for organization,
report title/reference/date, office and embedded logo, section headings, template
notes, signoff introduction and editable signature blocks. Program defaults omit
issue date. The date remains editable per project and per report.
No table or file-version marker changes. Program defaults are copied only when
creating or explicitly editing a project; reads do not publish defaults. Existing
unknown keys survive legacy settings writers. ProjectEditor owns Undo/Redo and
ordinary Save/recovery. See the [report contract](../features/report-documents.md#estimate-defaults-signature-blocks-and-notes-templates).
