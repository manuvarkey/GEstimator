## Deliberate compatibility boundaries

* Numeric editing accepts bounded decimal arithmetic (`+ - * / **` with parentheses and bounded integer powers), not arbitrary Python execution. The analysis engine is unchanged; measurement callbacks retain their original arithmetic. Resource monetary/tax fields use existing HALF_UP currency rounding at entry. Schedule quantity edits use four places, as in GTK. Analysis arithmetic entry is rounded to six places. A legacy expression using Python functions or other operators needs a separate compatibility decision.
* Row clipboards are currently session-local. TSV cell paste handles spreadsheet matrices and repeated values over selected rows. Text-field clipboard behavior is native. The modern service never unpickles arbitrary clipboard text.
* Project transaction undo uses bounded SQLite backup snapshots (30 operations), covering relationships, rates, quantities and measurement metadata together. Draft analysis undo remains separate, matching the two editing contexts in GTK. Undo after a save conservatively marks the project unsaved. Recovery restores the last checkpoint as a working project. Undo history is session-local.
* Schedule deletion clears associations to deleted items while preserving measurement records and remarks; transaction undo restores the original links. Existing GTK can leave dangling integer IDs which SQLite may recycle. The modern deletion path avoids that silent reassociation without changing the file schema. Pre-existing broken associations are shown as missing in the measurement editor.
* The old migration method addressed a nonexistent literal `self.ScheduleTable` table. Its target is corrected to `ScheduleTable`, with a finally-close for the migration connection. A generated v1 fixture verifies the original stays unchanged and the migrated working copy retains its rates.
* Schedule/resource spreadsheet import is explicitly mapped and bounded to 10,000 data rows/100 columns per worksheet; oversized input is rejected, never silently truncated. It accepts arithmetic numeric cells, not references to other cells/functions. It does not replace the existing GTK import dialogs.
